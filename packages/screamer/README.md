# screamer

Elements: DOM trees bound to signals, without a virtual DOM. This is the package an app depends on, with any add-ons it uses.

| Module | What it has |
|---|---|
| `Screamer` | the prelude: `Element`, `text`, `dyn`, `each`, `component`, `mount`, the `Signal` and `Event` types, `signalSource`, `eventSource`, `batch`, `Owned`, `onCleanup`, `liftEffect` |
| `Screamer.Element` | `Element`, `element_`, `svgElement_`, `fragment_`, `text`, `dyn`, `each`, `component`, `foreign_`, `foreignWithFallback_`, `mount`, `instantiate`, `IsElement` |
| `Screamer.Element.Unsafe` | `instantiateWith`: instantiate under a root that provides another renderer backend |
| `Screamer.Renderer` | `Backend`, `browserBackend`, `createBrowserBackend`, `rendererKey`, `interactive`, `delegated`: the node operations every element goes through |
| `Screamer.Attribute` | `Attribute`, `property`, `attribute`, `booleanAttribute`, `styleProperty`, `attributes`, `on_`, `unsafeOn_`, `AttrValue` |
| `Screamer.Html`, `.Html.Attributes`, `.Html.Handlers`, `Screamer.Svg` | typed elements, attributes and handlers, generated by `npm run codegen:dom` |
| `Screamer.Html.Reflect` | the HTML form of each DOM property, for renderers that serialize (generated) |

Depends on: screamer-reactive, and the `web-*` packages.

## Renderer backends

Every node an element creates, moves or removes goes through the `Screamer.Renderer` backend that its scope's context provides; the default is the browser DOM. A server or hydrating renderer, written as a separate library, supplies its own with `Screamer.Element.Unsafe.instantiateWith`. When the backend is not interactive, `on_` attaches nothing and `foreign_` runs no setup (`foreignWithFallback_` shows its fallback instead). See [`docs/ssr.md`](../../docs/ssr.md).
