# screamer

Elements: DOM trees bound to signals, without a virtual DOM. This is the package an app depends on, with any add-ons it uses.

| Module | What it has |
|---|---|
| `Screamer` | the prelude: `Element`, `text`, `dyn`, `each`, `component`, `suspense`, `mount`, the `Signal` and `Event` types, `signalSource`, `eventSource`, `batch`, `Owned`, `onCleanup`, `liftEffect` |
| `Screamer.Element` | `Element`, `element_`, `svgElement_`, `fragment_`, `text`, `dyn`, `each`, `component`, `foreign_`, `foreignWithFallback_`, `portal`, `catchError`, `suspense`, `withLeave`, `withEnter`, `withMove`, `mount`, `instantiate`, `IsElement` |
| `Screamer.Element.Unsafe` | `instantiateWith`: instantiate under a root that provides another renderer backend |
| `Screamer.Renderer` | `Backend`, `browserBackend`, `createBrowserBackend`, `RendererKey`, `rendererKey`, `interactive`, `delegated`, `BoundaryKey`, `boundaryKey`: the node operations every element goes through |
| `Screamer.Attribute` | `Attribute`, `property`, `attribute`, `booleanAttribute`, `styleProperty`, `attributes`, `on_`, `unsafeOn_`, `AttrValue` |
| `Screamer.Html`, `.Html.Attributes`, `.Html.Handlers`, `Screamer.Svg` | typed elements, attributes and handlers, generated by `npm run codegen:dom` |
| `Screamer.Html.Reflect` | the HTML form of each DOM property, for renderers that serialize (generated) |

Depends on: screamer-reactive, and the `web-*` packages.

## Framework primitives

- `portal selector el` renders `el` into another element (a modal root), owned by the current scope: it sees the current context and is removed with its parent.
- `catchError handler el` is an error boundary: if `el` throws while it is built, or one of its effects throws later, its scope is disposed and `handler err` is shown in its place. Errors from the handler's element go to the enclosing boundary.
- `suspense fallback content` shows `fallback` until nothing is pending in `content` (`Screamer.Pending.settled`), for example until its `resource`s have loaded, then shows `content`. Later loading inside `content` does not bring the fallback back.
- `withLeave`, `withEnter` and `withMove` are the seams for animation, which screamer-motion builds on. Each provides a hook, through its own context key, to every `dyn` and `each` inside the element, and each hook runs only when the renderer is interactive:
  - `withLeave hook el` delays the removal of branches and rows, for exit animations. Their scopes are disposed at once, and each top-level node stays until `hook node done` calls `done`. The hook is an `Owned Unit` that runs in a leaving scope of its own, disposed when the node is detached: on `done`, when the enclosing `dyn` or `each` is disposed, or when `each` rebuilds the row's key while the node is still leaving (it finishes the old nodes first, so the old and new row are never shown together).
  - `withEnter { appear } hook el` runs `hook node` on each top-level node of a branch or row once it is inserted, in a child scope of the branch's or row's scope. It runs only for branches and rows a change to that `dyn` or `each` adds, not its initial build, unless `appear` is set; a build that hydrates never runs it.
  - `withMove hook el` makes `each` measure its kept rows' top-level elements before and after each change, and run `hook { node, before, after }` on those whose rect changed, for FLIP. A row's running move hook is disposed before the row is measured again.
  - `immediateLeave`, `noEnter` and `noMove` are the defaults, which cost nothing.

## Renderer backends

Every node an element creates, moves or removes goes through the `Screamer.Renderer` backend that its scope's context provides; the default is the browser DOM. A server or hydrating renderer, written as a separate library, supplies its own with `Screamer.Element.Unsafe.instantiateWith`. When the backend is not interactive, `on_` attaches nothing and `foreign_` runs no setup (`foreignWithFallback_` shows its fallback instead).
